Artifact 3: Machine Learning or Deep Learning? Choosing the Right Approach

AIML-500 Fundamentals of AI and ML · Workshop 2 · October 2026

Introduction

A lot of teams hear "AI" and jump straight to the biggest model they can find. In this class I wrote a report comparing machine learning and deep learning using two real examples, and it changed how I think about that choice. I'm sharing it here as a quick guide for engineers and product people deciding which approach fits their problem.

Description

The report looks at two real systems. The first is email spam filtering with Apache SpamAssassin's Bayesian classifier, a classic machine learning problem where people choose the features. The second is screening eye photos for diabetic retinopathy with a convolutional neural network, where the model has to learn the features from raw pixels. For each one I explain why the approach fits and why the other one doesn't.

Spam filtering (ML)Eye photo screening (DL)
Type of dataText with clear cluesRaw images
Who picks the featuresPeopleThe network learns them
Training data neededHundreds to thousands of emailsOver 100,000 labeled images
Computing powerA normal serverGPUs for training
Explaining a decisionEasyHard

Quick way to decide: if you could write the warning signs on a checklist, start with machine learning. If nobody could write that checklist, like the signs of disease in an eye photo, deep learning is worth the extra data and cost.

Objective

I wanted to understand the real difference between the two approaches, not just the definitions, and be able to defend a choice for a specific problem. Healthcare is where I build software, so I picked an example where the wrong choice could actually hurt someone.

Process

  • Picked one machine learning example and one deep learning example from the course lesson.
  • Found a real-world system for each and checked the facts against the original sources, including the FDA authorization and trial results for IDx-DR.
  • Wrote out why each approach fits its problem and why the other one doesn't, then compared them on data, features, compute, and explainability.
  • Revised the report twice so it reads in plain language instead of like a textbook.
  • For this portfolio, I pulled out the comparison table and a one-line rule of thumb so someone can get the main point without reading the whole report.

Tools and Technologies Used

  • Microsoft Word for the report
  • Claude (Anthropic) to help research the sources and draft and revise the report
  • Official documentation, peer-reviewed papers, and FDA-related sources for fact-checking

Value Proposition

Unique value: It turns a textbook comparison into a practical decision guide, backed by two real systems instead of made-up examples.

Relevance: Picking deep learning when a simpler model would do costs time, money, and explainability, which matters a lot in healthcare. This artifact shows I start from the problem and choose the approach that fits, which is the core of how I want to build AI.
